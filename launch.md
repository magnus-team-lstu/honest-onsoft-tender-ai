Перед защитой нужны две вещи: установленный `make` (`make --version` должен отвечать) и смерженные в main ветки `feature/checks-demo` и `feature/create-makefile`. Все команды запускаются из корня проекта в терминале VS Code. Смотрите в терминал, а для графиков переключайтесь в браузер.

## Сценарий показа жюри

**1. Тесты: система собрана и работает** (несколько секунд)
```powershell
make test
```
Показать, что все тесты прошли.

**2. Демо проверок: обязательный вопрос «покажите пойманный обман»** (около 5 секунд)
```powershell
make demo
```
Терминал напечатает 8 ответов, оценку `check.py` (индекс −75), таблицу проверок и строку `Итог: -75.0 → 12.5`. Пройдитесь по строкам «Кто что поймал»: какая проверка поймала какую ошибку.

**3. Цифры «было/стало»: моментально, по уже готовым ответам**
```powershell
make eval
make report
```
`make eval` печатает два раза индекс 98.6 и таблицу по типам вопросов. `make report` показывает, что на настоящих ответах модели проверки не дали ни одного ложного отказа.

**4. Дашборд**
```powershell
make dashboard
```
Откроется браузер на `127.0.0.1:8501`. Показать «C. Было / стало» и «B. Проверки». Закрыть: `Ctrl+C` в терминале.

**5. Живой вопрос жюри** (несколько секунд)
Создайте заранее файл `results/jury.csv`:
```
id;package;question
J-01;P01;Какой размер обеспечения исполнения контракта, в процентах?
```
При жюри откройте его, замените текст вопроса и пакет (`P01`…`P06`) на то, что спросили, сохраните и выполните:
```powershell
make control CQ=results/jury.csv CP=data/packages
Get-Content results/answers_control.csv
```
На экране будет ответ, цитата и файл.

## Полный прогон при жюри
Если попросят показать прогон целиком:
```powershell
make all
```
Ответы модели лежат в кэше, поэтому повтор пройдёт за секунды: в выводе будет `Новых запросов: 0. Из кэша: 71`. Если спросят, честно скажите, что это повтор из кэша, а первый прогон занял около 8 минут. Запускать «с нуля» при жюри не стоит: это 15 минут ожидания.

## Контрольный набор
1. Распакуйте выданный архив так, чтобы в проекте появились `control/questions.csv` и `control/packages/…`. Если внутри архива есть своя папка, например `school21-onsoft-data`, вытащите её содержимое в `control/`.
2. Проверьте имена файлов в пакетах, особенно файла изменений: проверка узнаёт его по началу `05_izmeneniya`.
3. Запустите:
   ```powershell
   make control
   ```
   Пути `control/questions.csv` и `control/packages` уже прописаны в Makefile по умолчанию. Если положили в другое место, укажите явно: `make control CQ=путь/questions.csv CP=путь/packages`.
4. Сдайте файл `results/answers_control.csv`. Код при этом не менять.

На 100 вопросов уйдёт примерно 10–12 минут, это моя оценка по вашим 8 минутам на 71 вопрос. Индекс по контрольному набору сами вы не увидите: правильных ответов в архиве нет, его считает жюри.

Учтите: `make control` при каждом запуске перезаписывает `results/answers_control.csv`. После живого вопроса жюри этот файл занят ответом на один вопрос. Поэтому контрольный набор прогоняйте после демонстрации или сразу скопируйте готовый файл под другим именем, например `answers_control_final.csv`.
