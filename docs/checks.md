# Проверки ответа (участник B)

Код лежит в `src/checks/`. Внешних библиотек нет, только стандартный Python.

## Подключение к пайплайну

`src/run.py` (ветка A) сам подхватывает проверки, если папка `src/checks/` есть:

```python
from src.checks import build_verify
answer_question(..., verify=build_verify(row["question"]))
```

Пока ветка B не влита, пайплайн использует свою простую проверку `quote_in_file`.

## Что проверяется

| Имя | Что ловит |
| --- | --- |
| `quote` | Цитаты нет в документах. В подсказке для повтора есть похожее место |
| `injection` | Цитата взята из фразы-команды внутри документа |
| `changes` | Ответ по старому пункту, который изменён в `05_izmeneniya` |
| `numbers` | Числа или даты из ответа нет в цитате и её предложении. Расчёт «процент × НМЦК» допускается |
| `units` | Вопрос «в месяцах», а в цитате месяцев нет |
| `negation` | В цитате «не установлено», а ответ «да» или число; ответ «нет» без отрицания в цитате |
| `conflict` | То же условие в другом документе с другим числом, а статус не «расхождение» |

Статусы «не знаю» и «нет в документах» проверки не отклоняют.

## Демо на восьми ответах

```
uv run python -m src.checks.demo
```

Один верный ответ и семь обманов по закупке P01, по одному на каждую проверку. В извещение дописывается фраза-команда для модели.
Индекс считает `data/check.py`: без проверок −75.0, с проверками 12.5, каждая проверка даёт +12.5.

## Замер

```
uv run python -m src.checks.report --answers results/answers.csv
uv run pytest tests/test_checks.py -q
```

`report` пишет `results/verdicts.jsonl` для страницы B дашборда (`dashboard/screens/02_B_checks.py`), `results/checks_report.json`
и `results/critics.json` для графика вклада проверок у участника C.
Тест на правильных ответах организатора следит, чтобы проверки не отклоняли верные ответы.
